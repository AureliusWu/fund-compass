# 完整基金与手工资产同步候选（物理 v6）

本页描述本地实现，不是已部署的 v9 发布说明。应用仍为 **8.0.0**；物理 IDB v6、后端 schema 9、同步 revision 与 Holding/Policy/Decision 版本互不替代。主应用仍不启用 Turso Owner 工厂。真实云迁移、耐久、独立恢复、Chrome/旧 PWA/多设备与自然任务门禁不因本页实现而关闭。

## 使用顺序

1. 已采用的完整 v5 工作区中，下载升级前完整文件，保留原字节和 SHA256，再选回本轮同 SHA 文件。独立确认后才执行 v5→v6；普通启动不升级。
2. 升级只是本机格式变化，不发网络请求。versionchange 保存固定升级 intent，后续 strict 事务初始化 current；两次提交不冒称单事务。中断只能凭原文件手动核定，缺库、缺 intent、额外行或后续编辑不能重建/覆盖。
3. 登录不等于同步同意。明确启用本轮完整读取后，再手动从 `since=0`、固定 upper 分页读取全部历史，折叠为完整 C。合法部分页的 upper 保留为防回退下限，但不是完整 C。
4. 初始预览逐项显示基金/账户和手工资产冲突、墓碑、账户更名整组选项及剩余待上传意图。旧基金 B 从未代表手工资产已经采用：基金按旧 B/L/C 协调，手工资产首次差异必须明确选择，不能伪造已应用的祖先。字段或选项改变后须重新预览、重新确认。
5. 确认初始协调只在同一 strict 事务应用新的 L 与完整 B=C，不发送、不生成假回执，不清 `local_pending`。历史观察、旧原文、映射、升级 intent 和原基金 sync 元数据保留。
6. 初始协调后，另行同意本轮完整原包核对。预览实际 B→L 的基金和手工资产意图，再独立确认保存原包；这一步仍不发送。全量操作受原 **200 项 / 128 KiB** 请求上限约束，不裁切或偷偷拆批。
7. 检查原包全部字段和删除项，独立确认后仅发送该原始字节一次。必须先严格持久化 `attempted`，才可进入真实 POST 边界。prepared 才能单独确认取消；attempted/unknown 不得取消、重制或重发。
8. 已决槽或原 POST 的部分记录不是完整确认。当前会话必须拿到实际 write/receipt 原响应，绑定同一原 id/hash，再完整拉取固定 upper 的 D，预览 B/L/D 三方 ACK。冲突含手工资产四字段及账户更名整组，墓碑不得静默复活；选择改变须重新预览并确认。
9. strict ACK 同时核完整前像、推进本机版本/slot/full-sync epoch、应用新 L/B=D、保存本机回执并清原包。不能以 revision 或 SHA 冒充身份认证、云耐久、HoldingVersion 或金融行动资格。**本阶段 v6 持仓分析仍暂停**，不走旧 fund-only 分析/同步路径。

## 已链接工作区的完整云端刷新

已有完整 B 且原包槽和 pending 均为空时，可以在同意完整读取后，手动拉取固定 upper 的全部 D，再预览、选择冲突并独立确认“仅刷新本机”。基金与手工资产均做真实 B/L/D 三方协调；本机存在未上传意图也可以刷新，不必制造编辑或先上传。预览显示实际变更和刷新后仍未上传的意图；同值收敛、ABA、生命周期和账户更名整组仍需明确选择，云墓碑不能复活。

刷新不发 POST、不核伪造云回执、不借初始 bootstrap 或 ACK 清包；只在同一 strict 事务核完整前像后保存 L'/B=D，并推进独立 localVersion、slot、full epoch 和完整 profile 的 `refresh` 本机回执。旧 v4 receipt codec 不因此扩展。原文、历史、升级 intent、旧 sync、0/null/负零、原时间或未知时间保留，不清 `local_pending`。真正 typed no-op 不写库、不推进版本或伪造回执；任一原包五态均阻断刷新。新 B 下的剩余意图仍须另行制包/发送/ACK。

字段/选项改变使旧刷新请求失效；本机提交后须完成真实后置读取与 Pinia 发布，才释放本轮未知 id/hash。另一 handle 在此期间提交更新，旧结果不能发布覆盖它。最近回执已被后续编辑覆盖时只能保持 unknown，不重放。**v6 分析仍暂停**，不能把这个本机同步出口当作完整分析来源、实际多设备或云耐久验收。

## 保全与未知结果

| 情况 | 允许动作 | 不允许推论或动作 |
| --- | --- | --- |
| 本机 link/refresh/prepare/cancel/ACK 丢响应，或后置 hydrate/发布失败 | 保留本页内原本机 id/hash，只核同版本原完整 profile 回执；允许读取保全原包 | missing 不证明回滚，不重放，不以新 id 再提交 |
| POST 超时、撤销、坏响应或实际已提交但响应丢失 | 原包保持 attempted/unknown；手动核原 id/hash 的云回执，导出或关闭 | 不自动重复 POST，不以缺失回执判断未提交 |
| 刷新后本机槽是 confirmed/conflict | 重开原工作区、重新同意、核当前会话真实原回执，再取完整 D | 历史槽状态不充当当前会话的响应来源证明 |
| 另一标签页修改基金、手工资产、历史或元数据 | 拒绝旧预览/前像，保留较新数据，重新读取 | 不将同版本或只比较基金的片面相等作为覆盖许可 |
| 退出、端点/会话/来源变化、关闭面板 | 撤销旧任务、隐藏私人响应；保留原未知标识与数据库原包 | 不重新打开旧私人结果；协调器不拥有或主动释放共享应用 handle，不自动恢复发送 |
| 缺库、结构损坏或超容量 | 固定拒绝并保全旧文件/存储 | 不回退 LS/Gist、不补表/补行、不丢原文或历史换成功 |

本机未知标识当前保留在应用 store 内存中，不能声称跨刷新永久保存。完整文件和独立分析任务导出也各有用途，不能相互冒充。

核心本机操作超时/撤销仍保留原 fail-closed 关闭保护，防止迟到导入继续写入；后续只能 existingOnly 重开原 target 并重核 adoption，不新建库或替换权威。这与协调器自行关闭共享应用数据库是不同边界。

## 格式与绑定

- v6 保留旧六个 store，增加 `portfolio_sync_metadata`，只允许 `intent`、`current` 两行。活动 profile 是 `owner-portfolio-sync-1` / `fund-manual-1`，旧 `sync` 作为历史不再驱动新 sender；旧 outbox CAS 在 v6 仍全部拒绝。
- 活动 pending 不仅绑定基金，还绑定完整 portfolio、历史、原档案/intent、旧 sync、基线与版本。每次重读核原 raw SHA、实际 B→L wire 意图及完整 preparation envelope；不重制/替换留存的原字节。SHA 是本机绑定，不是来源认证或任意 raw-JS 防篡改证明。
- `sinan-owner-workspace-recovery-3` 仅认物理 v6，含完整本机状态与合法原 pending/原字节、所有旧档案和两次升级 intent。仍受 **24 MiB** 完整文件上限，写入前核可导出性。允许核 prepared/attempted/unknown/confirmed/conflict 的完整文件，不因此授予重发能力。
- recovery-2 只认物理 v5，recovery-1 只认 v3/v4。解码/下载成功不等于丢库恢复；本阶段没有通用 disaster restore、降级或远端 schema 迁移入口。
- 0、null、-0、未知时间、删除项和零份账户身份分别保留；wire 数字零遵循原请求合同，不改本机或完整基线原值。观察历史只留本机，不上传、不伪造现金流或收益。

## 验证边界

真实核心/Pinia/SFC 与 fake-IDB、合成 HTTP 的测试覆盖升级中断、最终事务竞争、完整原包状态、丢响应回执、字段/生命周期/更名冲突、完整 ACK、退出和迟到响应。它们不是实际 Chrome 下载、跨设备、旧缓存升级、Turso/Render 迁移、远端持久化或独立恢复证据。

发布时须另核 exact SHA 的 CI、类型/全量测试、构建/PWA/官方审计及包体和完整静态依赖闭包/安装预缓存；懒加载本身不是安装网络优化。详细本次计数和剩余性能债务记录在执行日志及独立测量报告，不能沿用旧候选的 PASS 作为新源证明。

三个实际 reader（同步 candidate、分析完整来源、v6 初始读取）现在使用同一固定有界折叠器：每页先严格解析，保留合法 upper 防回退，再核全部原始响应累计 **4 MiB**（含空白/重复覆盖历史）、历史 **100000** 项、保留完整像 **2 MiB**；单响应、原总时限和各 caller 的来源/分页守卫不放宽。按每键字节差量核保留像，不在每页重编码整 Map。超量或末页不满足真实完整基线 codec 即整次拒绝、不能发布完整 D；这不是进程堆内存的硬上限，也不是来源认证。
